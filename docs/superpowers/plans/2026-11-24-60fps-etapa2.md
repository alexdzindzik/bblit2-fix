# 60 fps, etapa 2: interpolação do cenário, da câmera e dos modelos — plano

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Os quadros extras deixam de repetir o tick e passam a mostrar o caminho entre os dois últimos ticks: cenário e câmera suaves, e também os modelos 3D (personagens, objetos), que usam o mesmo caminho no jogo.

**Architecture:** Ganchos nas funções do jogo que escrevem no pool de vértices marcam cada posição do pool com uma chave estável (bloco do cenário ou malha do modelo, mais o número do ponto). O gravador guarda essa chave em cada vértice. A cada tick novo, o mod casa os vértices do tick B com os do tick A pela chave e, na espera do jogo, desenha os quadros com a posição interpolada no espaço de vista (`src/interp.c`, puro e testado). Com a interpolação ativa, o quadro do próprio jogo não é mostrado: todos os quadros saem do mod, 1 tick atrás.

**Tech Stack:** C11, MinGW-w64 i686, gcc no Linux para os testes, OpenGL 1.1 do jogo.

**Spec:** `docs/superpowers/specs/2026-11-24-60fps-design.md` (Desenho §3, §4, §2; Etapas, itens 2 e 3).

## Global Constraints

- Tudo da etapa 1 continua: `fps=30` = 0.13.1; só o exe PT-BR; commit e push só com o OK do Night, no ramo `60fps`.
- Endereços medidos (24/11, sonda do pool):
  - pool de vértices: início `[0x4d0844]` (malloc de `0x111700` = 70 000 posições de 16 bytes), base do objeto atual `[0x4d0848]`, posições usadas `[0x4d084c]`; zerados por quadro em `0x401960`.
  - registro do pool: `{ X tela, Y tela, z vista, visível }` (floats). Tela = vista × K / D, com D = z + 1 se z ≥ 0, senão −z (`0x408d00`).
  - textura: `glTexCoord4f(s·q, t·q, 0, q)` com q = 1 / |z| (`0x422f70`).
  - cenário: `0x405470(bloco*)` abre o bloco no pool (base = início + `[0x4d084c]`·16), soma `[bloco + 0x10]` vértices e escreve o ponto i na posição i. Chamado em `0x4052df`, `0x405314`, `0x405349`, `0x40537e`, `0x4053b3`, `0x4053e8`, `0x405419`, `0x405459`.
  - modelos: `0x406d90(malha*, a, b)` e `0x406df0(malha*)` transformam `malha = { vértices*, n }` (vértice de 8 bytes; posição no pool = `[0x4d0848]` + (palavra +6 & 0x7fff)·16). Chamados em `0x464721`, `0x469b16` e `0x463f62`, `0x469ad5`.
- Sprites, efeitos 2D e HUD (escritos direto no pool, sem essas funções) ficam sem chave e saem como no tick B nesta etapa.

### Task 1: Matemática da interpolação (`interp`)

**Files:** Create `src/interp.h`, `src/interp.c`; Test `tests/test_interp.c`; Modify `build.sh`.

**Interfaces — Produces:**
- `double ip_div(double z);` (z ≥ 0: z + 1; senão −z)
- `void ip_vertex(const float a[3], const float b[3], double alpha, float out[3]);` (a, b = X, Y de tela e z de vista; interpola (X·D, Y·D, z) e volta para tela com o D do z novo)
- `double ip_dist(const float a[3], const float b[3]);` (distância no espaço de vista, mesma unidade de z)
- `void ip_texcoord(const double tc[4], double z, double out[4]);` (troca q por 1/|z|, mantendo s e t; q = 0 ou z = 0: copia)
- Mapa de chaves: `typedef struct { unsigned *key0, *key1; int *val; int cap, n; } IP_MAP;` `void ip_map_init(IP_MAP *m, unsigned *k0, unsigned *k1, int *v, int cap);` (cap potência de 2) `void ip_map_clear(IP_MAP *m);` `int ip_map_put(IP_MAP *m, unsigned k0, unsigned k1, int val);` (0 = cheio) `int ip_map_get(const IP_MAP *m, unsigned k0, unsigned k1);` (−1 = não tem)

- [ ] **Step 1: testes** (`CHECK` como nos outros):
  - `ip_div(0) == 1`, `ip_div(9) == 10`, `ip_div(-4) == 4`.
  - `ip_vertex` com alpha 0 e 1 devolve a e b (tolerância 1e-3); com a e b de mesmo z, alpha 0,5 dá X e Y no meio; com a = (100, 0, 9) e b = (100, 0, 19) (mesmo x de vista se aproximando... x_vista = 1000 e 2000), alpha 0,5: z = 14 e X = 1500/15 = 100.
  - `ip_dist((0,0,9),(0,0,19)) == 10`; `ip_dist((10,0,9),(0,0,9)) == 100` (X·D).
  - `ip_texcoord({2·0,1, 4·0,1, 0, 0,1}, 20)` → `{2·0,05, 4·0,05, 0, 0,05}`; com q = 0 copia.
  - mapa: put/get de 3 chaves; chave ausente → −1; `cap = 4` cheio → `put` devolve 0; `clear` esvazia.

### Task 2: Chaves no pool (`bbfix.c`)

**Interfaces — Produces:**
- `#define TAG_CAP 70000` e `static unsigned g_tag_k0[TAG_CAP], g_tag_k1[TAG_CAP]; static unsigned short g_tag_fr[TAG_CAP]; static unsigned short g_tag_frame;` (posição do pool → chave; vale só se `g_tag_fr == g_tag_frame`)
- `static void tag_range(DWORD first_slot, unsigned k0, unsigned base_local, int n);` e `static void tag_slot(DWORD slot, unsigned k0, unsigned local);`
- `static int patch_call(DWORD site, DWORD expect_target, void *fn);` (confere que o `E8` em `site` chama `expect_target`; troca pelo `fn`)
- `static void __cdecl bbfix_room(void *bloco);` → antes de chamar `0x405470`: `first = [0x4d084c]`, `n = [bloco + 0x10]`, `tag_range(first, (unsigned)bloco, 0, n)`.
- `static int __cdecl bbfix_mesh_a(void *malha, int a, int b);` e `static int __cdecl bbfix_mesh_b(void *malha);` → para cada vértice i da malha: posição = (`[0x4d0848]` − `[0x4d0844]`)/16 + (palavra +6 & 0x7fff); `k0` = ponteiro dos vértices, `k1` = (ocorrência dessa malha no quadro << 16) | i; depois chamam o original e devolvem o retorno dele.
- Ocorrências: tabela pequena por quadro (ponteiro → contador), zerada junto com `g_tag_frame++`.

- [ ] **Step 1:** `patch_call` e os patches, só com `g_rec_on` (fps > 30); um patch que não confere desliga a interpolação (log), não o mod.
- [ ] **Step 2:** `g_tag_frame++` e a tabela de ocorrências zerada no `rec_start` (começo de cada quadro do jogo).
- [ ] **Step 3:** no `rec_vtx`, se o ponteiro cai no pool (`[0x4d0844]` até + `TAG_CAP`·16) e a posição tem marca do quadro atual, gravar `u[1] = k0`, `u[2] = k1 + 1` (0 = sem chave).
- [ ] **Step 4:** `bash build.sh` → ok, sem avisos novos.

### Task 3: Par de ticks e repetição interpolada (`bbfix.c`)

**Interfaces — Consumes:** `interp.h` (Task 1), chaves (Task 2). **Produces:**
- Três instantâneos: `g_rec` (gravando), `g_show` (B, último completo), `g_prev` (A); no `rec_finish`, rodam A ← B ← gravado. Cada um com `t` (QPC do fim) e `tick` (`[0x4d0708]`) e `ok`.
- `static int g_pair_ok;` (A e B ok e `tick_B == tick_A + 1`)
- `static void pair_prepare(void);` (no `rec_finish`): mapa das chaves de A → índice do vértice; para cada vértice de B com chave: índice em A ou −1; objetos (`k0`) com algum vértice sem par ou com `ip_dist` maior que o limite (`fps_jump`, padrão 2000) vão inteiros como em B; liga cada `GR_TEXCOORD` ao `GR_VERTEX` seguinte do mesmo `glBegin`.
- `static void replay_ip(double alpha);` (repete B; vértices com par: `ip_vertex(A, B, alpha)`; texcoord ligado: `ip_texcoord` com o z novo; o resto como em B)

- [ ] **Step 1:** rotação dos 3 instantâneos (memória: 3 × `REC_CAP`) e os campos `t`, `tick`, `ok`.
- [ ] **Step 2:** `pair_prepare` com os mapas (`IP_MAP` de `REC_CAP`·2 arredondado para potência de 2) e as listas por comando (`int` por comando).
- [ ] **Step 3:** `replay_ip`.
- [ ] **Step 4:** `bash build.sh` → ok.

### Tarefa extra: bordas da tela ao girar a câmera

O jogo corta o cenário para a câmera do tick: 0x409950 tira o bloco se os 8 cantos passam do mesmo limite de tela
[0x639f18..24], e os pontos fora dos limites marcam os polígonos. O quadro intermediário usa uma câmera entre A e B:
faltava o que B cortou (cenário sumindo na borda de trás) e o que A cortou ficava sem par (vermelho na borda da frente).

- `ip_widen(b, fx, fy, out)` em `src/interp.c`: limites multiplicados em volta do centro. Teste: `test_widen`.
- `bbfix_walk` no lugar das 3 chamadas da árvore de salas (0x4068a9, 0x406903, 0x406954 -> 0x4052b0): alarga X por
  1,75 e Y por 1,5 durante a caminhada e devolve os limites depois. Só com fps > 30.
- Log de depuração: maior número de comandos por tick e ticks que não couberam no instantâneo (REC_CAP).
- Tentativa descartada: refazer a conta do cenário com a câmera de A (a matriz 0x63c020 muda entre blocos do mesmo
  tick e isso não resolve a borda de trás).
